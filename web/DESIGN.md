# FactLock DESIGN.md — 画面をつくる前に必ず読む

**版**: v1.16（2026-09-24）｜**出典**: `SEMANTICBASE_brand_guideline_v3`（色・Office書体）＋ Design System「SEMANTICBASE」（claude.aiの非公開キャンバス。このリポジトリは公開されるため、URLは本文に記載しない。所在はSEMANTICBASE Projectsの `resources.md` を参照）
**目的**: セッションを跨いでデザインの判断が平均（Inter・紫グラデーション・角丸カード3枚）に戻らないよう、方向・禁則・トークンをここに固定する。`web/styles.css` の `:root` はこのファイルの値と一致させる。

## 1. 方向性（名指し）：Ledger（監査済み台帳）

検証者が監査した印刷物の運用報告書。**紙が画面**であり、階層は文字サイズと余白で作る。各数値の証拠は、その段落の横の余白に脚注として並ぶ。検印（seal）が「監査に通った」ことを示す。

- 強調は1か所だけ：出典に固定された数値の下線 `--blue` `#00A1E0`。ほかは `--navy`・`--ink`・罫線のみ
- 内容を箱で囲まない：カード・枠線・影でグループ化しない。節＝`--navy` の見出し＋下に罫線 `--rule`＋上に24px
- 数値は内容であって装飾ではない：本文と同じ書体の600・`font-variant-numeric: tabular-nums`。小さなラベルに等幅書体を使わない
- 証拠はサイドパネルではなく余白の注記：右列13px `--ink-soft`、算出内訳は罫線だけの表
- 状態は帯ではなく印：合格＝`--green` の8px丸、注意＝`--gold`、差し戻し＝`--orange`。全幅の色帯は使わない
- 実データのみ：ファクトシートの値か実機の生成結果。架空の統計・Lorem ipsum禁止

## 4. 配置（A4縦を正とする・v1.2）

- **紙＝A4縦**（210×297mm＝794×1123px@96dpi）。画面でも印刷でも同じ紙を使い、印刷専用の別レイアウトは作らない（「見えないまま印刷だけ崩れる」欠陥を構造的に排除する）。CSSは `@page { size: A4 portrait; margin: 15mm }`、紙の内余白は上下56／左右56px
- 紙の内側は幅682：**本文440＋ガター24＋余白注記218**。本文は英文14.5px／1.7、和文13.5px／1.9、注記11.5px／1.5、表11.5px、表題32px、節見出し20px、図表題13px
- 画面（1280幅）は「ヘッダー帯（56px）＋操作行（規則の一文とApprove／Copy／Print）＋机の上に置いたA4シート」。シート以外の要素は印刷しない（`@media print` でヘッダー帯・操作行を非表示）
- ヘッダー帯の右端に「Sign out」（v1.10）。合言葉が有効なとき（`/api/health` の `gated`）だけ表示する。ボタン様式を増やさないため、帯のラベルと同じ13px・`--blue-light` の下線付き文字とする。1280幅で帯は1行のまま（制御部品705／帯の内幅1152、2026-09-24にIBM Plexで実測）。390幅では帯の折り返しが1行増える（許容）。押すとCookieを消して合言葉画面に戻り、「You have signed out on this browser.」を表示する
- 下書き前（空の状態）の案内（v1.11）：操作行は規則の一文の代わりに太字で「To begin, press “Draft it live with Gemini” at the top right.」と続く説明を出す。紙面は「How to use this demo／このデモの使い方」（見出しは `.h3`、手順は番号付き3行、本文は `.p-en`／`.p-ja`）を表示し、印刷しない（`.screen-only`）。下書き後は消える。帯の部品に番号を振る案は、操作が1つしかないのに3つ必要と読めること、下書き後の次の操作が帯ではなく操作行にあることから採らない（2026-09-24、Satoshiさん承認）。ボタン名は現在の表示文字（作成中は「Drafting…」）ではなくモードから決める。案内の節は下の2節と同じ全幅（`wide`）とする（v1.13）
- 文章事実の和文は名詞の形にする（v1.14）：連続月数は「16か月連続の上昇」「直近16か月にわたる上昇」「直近1か月で上昇に転換」「前月から横ばい」。「〜しています」で終わる形は、書き手が文を続けると崩れる（2026-09-24の40本で5本、すべてこの文言が原因）。騰落率の動詞形が名詞句であるのと同じ原則
- 注記の「from notes」（v1.13）：入力に自分の注記がなくても、同じ値で本文に出ている別名（例：SPYの寄与度＝「最大の寄与度」）の注記を指す。それでも本文にない入力があるときは「and N inputs not cited in the text／本文にないN件の入力」と書き、合計が短く見えないようにする。注記は自分自身を指さない（2026-09-24の本番PDFで、4資産の合計である騰落率の注記が「from notes 13 and 14」となっていた）
- ヘッダー帯の選択欄（v1.11）：ブラウザ標準の矢印は右の余白を揃えられないため、`appearance: none` で消し、`--blue-light` の矢印を描く。見た目の余白は左右とも11.5px（文字は内余白10px＋字形の左余白約1.5px、矢印は右から11px。2026-09-24、IBM Plex・2倍で実測）
- 8pxリズム。**すべて左揃え**（検印の内部文字のみ中央）。改ページ：図表・検印つき見出し・台帳表は `break-inside: avoid`
- **ページは「1枚＝1ページ」で組む（v1.3）**。各ページの下端に罫線＋文書名＋「n of N」、2ページ目以降の上端に小さな柱（ファンド名／月）。ページの内余白は上56・左右56・下40
- **キャンバスでの試作**：A4は「固定ページの連作」（1アートボード＝1ページ、専用のキャンバスページに順に並べ「All artboards (.pdf)」で書き出す。画面のアートボードを「PDF (.pdf)」で書き出すと、そのアートボードの寸法の1枚のPDFになる）。流し込み（flow）は使わない——書き出し側が①横並びの列をページ高で輪切りにし②改ページごとに約53pxを足し③改ページを指定できないため、2列の紙面が崩れる（2026-09-23、2ページ設計が3ページに分かれた原因）
- **製品での実装**：ブラウザ印刷。`@page { size: A4; margin: 0 }`＋ページ容器（高さ297mm・`break-after: page`）、注記は文と同じ行に置き `break-inside: avoid`。ページ番号と柱はページ容器に描く（またはChromeの `@page` マージンボックス）。月ごとに文章量が変わるため、ブロック単位で次ページへ送る処理を実装で持つ

## 4.5 節の構成（製品と一致させる）

節の順序と見出しは `app/models.py` の `SECTIONS` に従う：**市場環境（Market environment）→ 運用経過（Fund performance）→ ポートフォリオ（Portfolio）→ 今後の見通し（Outlook）**。紙面では節ごとに英文段落→和文段落の順に置く（v1.4で4節すべてを試作に反映）。

**印刷の言語（2026-09-23確定）**：印刷は画面の言語切替に従う。英語のみ・日本語のみはA4 2ページ、英日併記は3ページを目安とする（試作は英日併記の3ページ：1＝表題と市場環境、2＝運用経過とデータ検査・出所、3＝ポートフォリオ・今後の見通し・検証の記録と承認欄・免責）。実際の下書きは月ごとに長さが変わるため、実装では節単位で次ページへ送る。

**今後の見通し**は数値を持たない（下書き規則で予測を禁じている）。余白には番号のない「Drafting rule」注記を置き、規則が効いていることを紙面で示す。

**承認欄**：3ページ目の「How this draft was checked」の4行目に、印刷して回覧する場合の手書きの承認欄（Reviewer／Date）を置く。画面の「Approve draft」は名前と時刻を記録する。

文字サイズ：注記11.5px・注番号9.5px・検印8.5px は印刷の目安（脚注12px以上）を下回るが、2026-09-23にSatoshiさんがPDFで確認し「このままで問題ない」と判断した。以後の改訂で機械的に拡大しない。

## 5. モチーフ

- **固定数値**：ネイビー600＋下線2px `--blue`＋上付きの注番号（9px `--ink-soft`）。**淡い水色の地（`--lock-tint`）と外枠線は、画面で選択中の数値だけ**に付ける（v1.4：全数値に地色を敷くと本文が読みにくくなるため外した）。同じ注記を指す数値は同じ番号を共有してよい（例：目標配分4つ→注記13）。**注番号は下線の外に置き**（下線は数値だけを示す）、数値と注番号は改行で離さない（`white-space: nowrap` の入れ物で包み、注番号は `line-height: 0` で行間を乱さない）
- **選択状態は画面だけ**：選んだ数値の外枠線と、注記の展開（淡い水色の囲み）は画面でのみ表示し、印刷では全注記を同じ形で出す。「Select a number…」の案内文も画面専用
- **検印**：直径96px・2pxの `--navy` 環・`--ui` 700で「検証済」、下にVERIFIED、11pxで件数と日付。円形要素はこれだけ。傾き−6°を許す唯一の要素
- **台帳表**：行は `--rule`、合計の上は `--rule-strong`、数値は右揃え
- **図表（exhibit）**：本文列の中に置く罫線だけの表・図。**青い下線と注番号は「本文中の数値」だけに使う**（書き手エージェントが書き、規則審査が照合した主張であることの印）。図表の数値はファクトシートからプログラムが直接描くため、通常の数字（`--display` 600・タビュラー）で書き、証拠は図表直下の「Source」段落とする（J.P. Morgan資料と同じ作法）。❌撤回（v1.3）：v1.1〜v1.2の「図表内の数値も固定数値として注番号を持つ」——注番号が増えて余白注記が紙面を押し出し、青の意味も二重になったため
- **4局面マトリクス**：列幅20／40／40％・`table-layout: fixed`・見出し行28px・データ行56pxの等高。**セルの中身は2行に固定**（局面名＋該当地域名、または「none this month」）し、数値はマトリクスの下の台帳（地域／先行指数の前月差／金利の前月差／局面）へ出す。v1.2は数値をセル内に入れたため行が内容で伸び、等寸にならなかった。金利系列のない地域は台帳に「not placed」として載せる
- **寄与の積み上げ図**：台帳の各行に横棒を入れ、各棒は前の棒の終点から始める（最後の棒がファンドの騰落率に届く）。**資産ごとの棒は `--blue`、合計（ファンド）の棒は `--navy`**。1.0・2.0 に淡い縦罫を引き、**目盛の数字（0・1.0・2.0）を見出し行に置く**（縦罫の意味を出所段落で文章説明しない）。単位は製品の表記に合わせ pp。合計行の上は `--rule-strong`
    - v1.6（2026-09-23、Satoshiさんのご指摘）：v1.3〜v1.5は棒をネイビー1色にしており、見出し・本文の数値と同じ色で図が沈んでいた。§5.5で定めた「系列は主役1色（ブランド青）」とも食い違っていたため是正
    - `--light-blue`（`#7FD1EF`）は白地で1.7:1と淡く、白黒印刷で消えやすいため棒には使わない。`--blue` も白地で2.9:1と図形の目安（3:1）をわずかに下回るため、**棒には必ず数値を併記する**（色だけで情報を伝えない）
- 図表の直下の Source 段落は11px `--ink-soft` で1〜3文（定義・基準日・出所）。
- **紙面末尾の「Sources」**：発行者・データセット名・利用条件を1行ずつ、見出しに取得日（Sources, retrieved 20 September 2026）。直下に「前月差・局面・寄与・ルックスルー比率はFactLockが算出した」と明記する（CC BY 4.0 §3(a)(1)(B) は加工した場合にその旨の表示を求める）。データ検査と出所は本文2列の外、紙面の全幅に置く円形の図・グラデーションの矢印・凡例の色バッジは使わない

## 5.4 単位・記号・改行（v1.7）

**単位は製品の整形関数（`app/render.py` の `format_fact`）の出力に合わせる**。試作が製品と違う単位を使うと、実装後に紙面と画面が食い違う（2026-09-23、試作の寄与「1.08 pt」が製品では「+1.08 pp」だったことを検出）。

| 種類（`unit`） | 英語 | 日本語 |
|---|---|---|
| 騰落率・配分（`pct`・`weight`） | 2.71%／40.0% | 2.71%／40.0% |
| 寄与（`contrib`） | 1.08 pp | 1.08% |
| 金利の変化（`pp`） | 0.08 pp | 0.08%ポイント |
| 指数の変化（`pt`） | 0.08 pt | 0.08ポイント |
| 指数の水準（`index`） | 100.88 | 100.88 |

- 符号：プラスは英日とも半角「+」。マイナスは紙面では数学の負号「−」（U+2212）で表示する。製品の整形関数はASCIIの「-」を出すため、表示層で置き換えるか整形関数を変えるかを実装時に決める
- **改行禁止スペース**：数値と単位（0.08 pt）、日付（31 August 2026）、「CC BY 4.0」「trend = 100」「note 9」は途中で改行させない。2026-09-23のPDFで「4.0.」「months”.」「pt).」が行頭に1語だけ落ちていた

## 6. 禁則（記事「平均への収束」と自社の自己点検から）

- Inter・Roboto・Arial・system-ui（Web）／紫・藍のグラデーション／角丸カードの3枚並び／中央寄せヒーロー
- 内容を囲む枠線・影（`0.1`不透明度の影を含む）／左枠線カード／全幅の色帯／bento式の角丸カード格子（`DigitalPortfolio_Spec` §10.2のダッシュボード専用。FactLockには持ち込まない＝2026-09-23確定）
- 全大文字のラベル／見出しごとの小見出しラベル（eyebrow）／中黒でつないだメタ情報「A · B · C」／小ラベルの等幅書体／リンク末尾の「→」／絵文字
- 単語1つだけ色や太字を変える見出し／ホバーごとのアニメーション・節ごとのフェードイン
- **ヘッダー帯・操作行の文字の折り返し**（v1.4）：ボタン・選択欄・ラベルは `white-space: nowrap; flex-shrink: 0`。縮んでよいのは説明文（タグライン）1つだけで、`min-width: 0; overflow: hidden; text-overflow: ellipsis`。制御部品の幅の合計は、容器幅に対して約1割の余裕を残す（2026-09-23、1280幅で「EN + 日本語」「Draft it live with Gemini」が折り返してはみ出した。原因は部品の合計幅が容器を超え、flexがボタンを縮めたこと）
- **表のセルで `nowrap` と `overflow: hidden` を組み合わせない**：文字が黙って欠ける。折り返しを許すか、列幅を書体の実寸で見積もる
- **列幅は先頭行のセルに指定する**（`table-layout: fixed` と併用）。`<colgroup>`／`<col>` の幅は、キャンバスの試作では無視され、全列が等幅になった（2026-09-23、書き出したPDFで4局面・台帳・寄与の図の3表すべてが等幅だったことを確認）。先頭行のセル指定はブラウザでも同じく効く
